# frontend

**함께하개**는 반려동물과 함께 갈 수 있는 장소를 찾고, 우리 아이가 그곳에
들어갈 수 있는지 판정해 주는 서비스입니다.

이 저장소는 그중 **사용자와 운영자가 보는 웹 화면**입니다.
장소를 찾고(메인 · 검색), 동반 조건과 그 근거를 보고(장소 상세), 일정을 담아 카카오맵으로 길을 안내받고,
반려동물 · 즐겨찾기 · 후기 · 알림을 관리하는 화면과, 운영자가 제보를 처리하고 데이터를 고치는 관리자 화면이 들어 있습니다.
화면은 게이트웨이(gateway-server) 하나만 부르고, 그 뒤의 도메인 서비스는 게이트웨이가 나눠 부릅니다.

---

**먼저 전체 그림을 보고, 이 레포가 그 안 어디에 있는지 본 뒤 읽습니다.**

**① 전체 구조 — 층으로 본 것.** 위에서 아래로 요청이 내려가고, 어느 층에 무엇이 있는지. 이 레포는 요청이 시작되는 쪽(브라우저)입니다.

![전체 구조 (층)](https://raw.githubusercontent.com/paw-trail/service-template/main/docs/architecture-layers.svg)

**② 전체 구조 — 서비스끼리 무엇을 주고받는지.** 초록 실선이 `/internal` 호출, Kafka 표가 이벤트, 하늘색 점선이 VPC 경계. 화면의 요청은 전부 게이트웨이로 들어갑니다.

![전체 구조 (호출 관계)](https://raw.githubusercontent.com/paw-trail/service-template/main/docs/architecture.svg)

**③ 이 레포를 중심으로.** 직접 연결된 것만 남긴 그림은 service-template 의 그림 스크립트로 뽑아 `docs/focus-frontend.svg` 에 둘 예정입니다.
그때까지는 [0-3](#0-3-부르는-곳)의 표가 그 역할을 합니다.

## 먼저 알아 두면 좋은 것

이 문서에 자주 나오는 말 5가지입니다. 백엔드 쪽 용어는 [service-template 의 용어 장](https://github.com/paw-trail/service-template#11-용어)에 있습니다.

**개발 서버와 프록시.** `npm run dev` 로 띄우는 개발 서버(Vite)는 화면 파일을 내주면서, 화면이 부르는 `/api` 로 시작하는 요청을 게이트웨이(`localhost:8080`)로 넘겨 줍니다.
브라우저 입장에서는 화면과 API 가 같은 주소(`localhost:5173`)라 CORS 오류가 나지 않고, 로그인 쿠키도 그대로 실립니다([6장](#6-개발-서버-프록시)).

**HttpOnly 쿠키 로그인.** 로그인하면 서버가 토큰을 자바스크립트가 읽을 수 없는 쿠키(HttpOnly)에 넣어 줍니다.
그래서 화면은 토큰을 직접 들고 있지 않고, 로그인했는지는 `GET /api/v1/auth/me` 로 서버에 묻습니다.
로그아웃도 화면이 쿠키를 지울 수 없어서, 서버가 만료된 쿠키를 내려 주는 방식입니다.

**서버 상태 (TanStack Query).** 서버에서 받은 값은 「열쇠」를 붙여 한곳에 모아 두고(캐시), 같은 열쇠를 쓰는 화면끼리 나눠 씁니다.
값을 바꾸는 요청을 보낸 뒤에는 관련 열쇠를 「무효화」해서 다시 받게 합니다([5장](#5-서버-상태-규칙)).

**판정 기준.** 같은 장소라도 반려동물마다 들어갈 수 있는지가 다릅니다(체중 · 견종 · 이동장).
그래서 화면 전체가 「지금 판정 기준인 반려동물」을 하나 들고 있고(처음에는 대표 반려동물), 판정을 부를 때 그 id 를 함께 보냅니다.
기준은 메인 · 검색 화면 아래 띠의 [기준 변경하기]나 장소 상세의 [기준 바꾸기]로 바꿉니다.

**rem 과 배율.** 화면의 크기는 대부분 `rem`(뿌리 글자 크기의 배수)으로 잡혀 있습니다.
창 폭이 1440px 까지는 뿌리 글자 크기가 창에 맞춰 커지고, 그보다 넓으면 16px 에 멈춰 본문이 가운데 1440px 안에 섭니다([4-4](#4-4-화면-폭과-배율)).

## 0. 이 화면이 하는 일

### 0-1. 한 문장

반려견 보호자가 **가려는 장소에 우리 아이가 들어갈 수 있는지를 근거와 함께 확인하고, 일정으로 묶어 길을 안내받는 웹 화면**입니다.

판정 · 검색 · 날씨 같은 판단은 전부 서버가 하고, 이 레포는 그 결과를 보여 주고 사용자의 입력을 서버로 넘깁니다.
판정이 「가능 · 조건부 가능 · 불가 · 확인 필요」 넷 가운데 무엇인지, 그 근거가 어느 기관의 어느 자료 · 어느 항목에서 왔는지를 화면에 그대로 드러내는 것이 이 화면의 중심입니다.

### 0-2. 화면 목록

명세서(기능 명세 1부)의 장 번호와 경로입니다. 명세서에 그림이 없는 화면은 장 칸을 비웠습니다.
관리자 화면(17~21장)은 계정의 역할이 `ADMIN` 일 때만 열립니다.

| 장 | 화면 | 경로 |
|---|---|---|
| 1 | 스플래시 (로그인 확인 중) | 경로 없음 — 로그인을 확인하는 동안 화면 앞에 뜸 |
| 2 | 로그인 | `/login` · 구글 로그인 결과 `/login/success` · `/login/error` |
| 3 | 계정 만들기 | `/signup` |
| 4 | 비밀번호 찾기 | `/password/reset` |
|  | 개인정보처리방침 | `/privacy` — 로그인 없이 열림 |
| 5 | 반려동물 정보 등록 | `/signup/pets` |
| 6 | 메인 | `/` |
| 7 | 검색 결과 | `/search` |
| 8 | 장소 상세 | `/places/{placeId}` |
| 9 | 후기 작성 | `/places/{placeId}/review` |
| 10 | 일정 확인 · 길 안내 | `/itinerary` |
| 12 | 마이페이지 — 동반 기록 | `/mypage` |
| 13 | 반려동물 정보 수정 | `/mypage/pets` |
| 14 | 즐겨찾기 | `/mypage/favorites` |
| 15 | 방문한 장소 | `/mypage/visited` |
| 16 | 작성한 후기 | `/mypage/reviews` |
|  | 최근 본 장소 | `/recent` · `/mypage/recent` |
|  | 계정 관리 | `/mypage/account` |
|  | 알림 설정 | `/mypage/notifications` |
|  | 문의 내역 | `/mypage/inquiries` |
|  | 알림 | `/notifications` |
| 17 | 관리자 — 제보 처리 | `/admin` |
| 18 | 관리자 — 장소 관리 | `/admin/places` |
| 19 | 관리자 — 조건 정정 | `/admin/policies` |
| 20 | 관리자 — 이벤트 재발행 | `/admin/outbox` |
| 21 | 관리자 — 운영 | `/admin/ops` |

11장(안내 시작)은 만들었다가 뺐습니다.
카카오맵 길찾기 주소는 경유지를 받지 못해서, 10장의 [안내 시작하기]가 「내 위치 → 첫 장소」 · 「첫 장소 → 둘째 장소」처럼 구간을 고르게 하고 고른 구간을 카카오맵 새 창으로 엽니다.
화면 파일(`GuidePage.tsx`)은 남아 있지만 경로에는 걸려 있지 않습니다.

### 0-3. 부르는 곳

화면의 요청은 게이트웨이 하나로 들어가고, 게이트웨이가 경로를 보고 서비스로 나눕니다(라우트 20개 — config 레포 `gateway-server.yml`).
화면별로 어떤 API 를 부르는지는 [대조표](docs/api-map/)에 있습니다.

| 경로 | 받는 서비스 | 화면에서 쓰는 곳 |
|---|---|---|
| `/api/v1/auth/**` | auth | 로그인 · 가입 · 이메일 인증 · 비밀번호 · 로그아웃 · 탈퇴 · 내 계정 확인 |
| `/api/v1/users/**` · `/favorites/**` · `/visits/**` · `/itineraries/**` | user | 프로필 · 즐겨찾기 · 방문 기록 · 일정 · 최근 본 장소 · 하루 요약 |
| `/api/v1/pets/**` · `/breeds` | pet | 반려동물 등록 · 수정 · 사진 올릴 주소 · 견종 목록 |
| `/api/v1/places/{placeId}` · `/documents` | place | 장소 상세 · 근거 원문 |
| `/api/v1/places/{placeId}/verdict` | verdict | 판정과 그 이유 |
| `/api/v1/places/{placeId}/conflicts` | policy | 출처마다 다르게 적힌 조건 |
| `/api/v1/search/**` | search | 검색 · 판정별 건수 · 자동완성 · 인기 급상승 · 지역 목록 |
| `/api/v1/reports/**` | report | 제보 · 문의 내역 |
| `/api/v1/notifications/**` | notification | 알림 · 안 읽은 수 · 알림 설정 |
| `/api/v1/weather/**` | weather | 날씨 띠 |
| `/api/v1/admin/**` | 경로마다 (auth · pet · place · policy · report · verdict · search) | 관리자 화면 |
| `/api/v1/places/{placeId}/reviews` · `/reviews/**` | review | 후기 목록 · 작성 · 수정 · 삭제 · 내 후기 · 좋아요 · 태그 목록 · 사진 올릴 주소 |
| `/api/v1/admin/reviews/{reviewId}` | review | 관리자가 신고된 후기를 내릴 때 |
| `/api/v1/admin/ingest/runs` | ingest | 21장 「공사 데이터 최신 수집」 실행과 실행 기록 |

게이트웨이를 거치지 않는 것도 둘 있습니다.

| 가는 곳 | 무엇을 | 언제 |
|---|---|---|
| S3 | 반려동물 · 프로필 사진 올리기 (pet · user 가 발급한 서명 주소로 브라우저가 직접) | 사진을 고르고 저장할 때 |
| 카카오 | 지도 SDK (브라우저가 직접) · 카카오맵 길찾기 새 창 | 상세 · 일정의 지도 · [안내 시작하기] |

### 0-4. 하지 않는 것

- **판정 · 검색 · 날씨를 화면에서 계산하지 않습니다.** 모두 서버가 준 값을 그대로 씁니다.
  예외는 거리 하나입니다 — 내 위치를 서버로 보내지 않으려고 거리만 브라우저에서 잽니다([8장](#8-위치-정보-원칙)).
- **휴대폰 화면을 따로 두지 않습니다.** 데스크톱 전용이며, 창 폭이 1280px 보다 좁으면 가로 스크롤이 생깁니다.

## 1. 로컬에서 띄우기

### 1-1. 전체 흐름

```
① 백엔드 컨테이너 (infra)  →  ② 설치 (npm ci)  →  ③ .env.local  →  ④ npm run dev  →  ⑤ http://localhost:5173
```

화면만 띄우면 로그인부터 막힙니다. 먼저 백엔드가 떠 있어야 합니다.

### 1-2. 백엔드 컨테이너

infra 레포에서 띄웁니다. infra 의 `.env` 에 `COMPOSE_PROFILES` 가 아래처럼 잡혀 있어야 합니다.

```
COMPOSE_PROFILES=infra,platform,db,tools,app,pipeline,observability
```

`pipeline` 이 빠지면 ingest · extract 가 뜨지 않아 **장소 상세의 근거 원문이 비고, 운영 화면의 수집 버튼도 동작하지 않습니다.**
`observability`(prometheus · loki · zipkin · grafana)는 화면에 필요하지 않아 빼도 됩니다.

Windows (PowerShell):

```powershell
cd C:\Tour_Prj\infra
docker compose up -d
docker compose ps --format "table {{.Name}}\t{{.Status}}"
```

macOS (터미널):

```bash
cd ~/Tour_Prj/infra
docker compose up -d
docker compose ps --format "table {{.Name}}\t{{.Status}}"
```

서비스가 전부 `healthy` 가 될 때까지 1~2분 걸립니다.
`docker compose` 에 `--profile` 을 붙이면 `.env` 의 목록이 통째로 바뀌므로 평소에는 붙이지 않습니다(infra README).

### 1-3. Node 와 설치

Node.js **20.19 이상** 또는 **22.12 이상**이 필요합니다(Vite 7 의 요구). `node -v` 로 확인합니다.

```bash
cd frontend
npm ci
```

`npm ci` 는 `package-lock.json` 에 적힌 판을 그대로 설치합니다. 판을 올릴 때만 `npm install` 을 씁니다.

### 1-4. 환경 변수 파일

`.env.example` 을 `.env.local` 로 복사합니다. `.env.local` 은 `.gitignore` 에 걸려 있어 커밋되지 않습니다.

Windows (PowerShell):

```powershell
Copy-Item .env.example .env.local
```

macOS (터미널):

```bash
cp .env.example .env.local
```

카카오 지도 키를 넣지 않아도 화면은 뜹니다. 지도 자리에 약도가 대신 그려집니다([2-2](#2-2-카카오-지도-키)).

### 1-5. 실행

| 명령 | 하는 일 | 주소 |
|---|---|---|
| `npm run dev` | 개발 서버 — 파일을 고치면 바로 반영 | http://localhost:5173 |
| `npm run build` | 타입 검사(`tsc -b`) 뒤 `dist/` 에 배포용 파일을 만듦 | — |
| `npm run preview` | `dist/` 를 개발 서버와 같은 프록시로 띄워 봄 | http://localhost:4173 |

`vite.config.ts` 나 `.env.local` 을 바꿨다면 개발 서버를 껐다 켜야 반영됩니다.

### 1-6. 떴는지 확인

1. http://localhost:5173 을 열면 스플래시가 잠깐 뜬 뒤 로그인 화면으로 넘어갑니다.
2. 계정이 없으면 3장 계정 만들기에서 가입합니다. 가입 인증 코드가 메일로 오므로 받을 수 있는 주소를 씁니다.
3. 가입이 끝나면 5장 반려동물 등록으로 이어지고, 등록하면 메인이 뜹니다. 메인 위쪽에 날씨 띠가 보이면 게이트웨이 뒤의 서비스까지 이어진 것입니다.

관리자 화면을 보려면 계정의 역할을 `ADMIN` 으로 바꿔야 합니다. 방법은 policy-service README 9-4 에 있고, 바꾼 뒤에는 **다시 로그인해야** 새 역할이 토큰에 실립니다.

## 2. 환경 변수

### 2-1. 목록

`.env.local` 에 둡니다. `VITE_` 로 시작하는 값만 화면 코드에서 읽힙니다.

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `VITE_API_PROXY_TARGET` | `http://localhost:8080` | 개발 서버가 `/api` 요청을 넘길 곳 (게이트웨이) |
| `VITE_KAKAO_MAP_JS_KEY` | 빈 값 | 카카오 지도 JavaScript 키. 비우면 지도 자리에 약도를 그림 |
| `VITE_FALLBACK_SIDO_CODE` | `11` | 처음 쓸 지역의 시도 코드 (서울) |
| `VITE_FALLBACK_SIGUNGU_NAME` | `마포구` | 처음 쓸 지역의 시군구 이름 |

### 2-2. 카카오 지도 키

카카오 개발자 콘솔에서 세 군데를 맞춰야 지도가 뜹니다.

| 어디 | 무엇을 | 틀리면 |
|---|---|---|
| [앱] > [플랫폼 키] > JavaScript 키 | 키 값을 `VITE_KAKAO_MAP_JS_KEY` 에 | — |
| 같은 키의 JavaScript SDK 도메인 | `http://localhost:5173` · `http://localhost:4173` 을 **포트까지** 등록 (배포하면 배포 주소도) | `sdk.js` 가 401 |
| [제품 설정] > 카카오맵 | 사용 설정을 켬 | 지도 요청이 403 (`OPEN_MAP_AND_LOCAL`) |

REST API 키가 아니라 **JavaScript 키**입니다. 같은 앱 화면에 둘이 나란히 있어 헷갈리기 쉽습니다.
키를 넣거나 바꾼 뒤에는 개발 서버를 다시 켭니다.

## 3. 폴더 구조

### 3-1. 나무

```
src/
├─ main.tsx            앱 시작 — React 를 붙이고 글꼴 · 스타일을 부름
├─ app/                라우터 · 쿼리 클라이언트 · 틀 묶음
├─ api/                서버 호출 — 서비스별 함수 · 응답 타입 · 캐시 열쇠 · 봉투 풀기
```

`@/` 는 `src/` 를 가리키는 줄임입니다(`vite.config.ts` · `tsconfig.app.json`). `import { api } from '@/api/client'` 처럼 씁니다.

### 3-2. 어디에 무엇을 두나

| 무엇 | 어디에 | 까닭 |
|---|---|---|
| 한 화면만 쓰는 부품 · 훅 | 그 화면의 `features/{이름}/` | 화면을 지울 때 함께 지워지게 |

| 서버 응답 모양 | `api/types.ts` | 레포 실물의 응답 DTO 이름을 주석으로 붙여 둠 |
| 화면 문구가 되는 이름표 (판정 · 출처 · 조건 항목 이름) | `lib/labels.ts` | 같은 값을 화면마다 다르게 부르지 않게 |
| 색 · 글자 크기 · 모서리 | `styles/index.css` 의 디자인 토큰 | Tailwind 클래스(`text-ink` · `bg-brand-soft`)로 씀 |

## 4. 화면 공통

### 4-1. 틀 넷

| 틀 | 쓰는 화면 | 들어 있는 것 |
|---|---|---|
| `AppLayout` | 로그인 뒤 사용자 화면 전부 | 머리띠 · 날씨 띠(탐색 화면만) · 가운데 본문 기둥 |
| `AuthLayout` | 2 · 3 · 4장 | 왼쪽 문구 + 그림, 오른쪽 카드 — 두 칸의 아래 끝을 맞춤 |
| `MyPageLayout` | 12~16장과 계정 · 알림 설정 · 문의 내역 · 최근 본 장소 | 위쪽 프로필 카드(숫자를 누르면 그 목록으로) · 왼쪽 메뉴 |
| `AdminLayout` | 17~21장 | 왼쪽 관리자 메뉴(멈춘 이벤트 수 배지) · 역할이 `ADMIN` 이 아니면 「관리자만 볼 수 있습니다」 |

### 4-2. 로그인 확인

로그인이 필요한 화면은 모두 `RequireSession` 을 거칩니다.
로그인 없이 열리는 화면은 2 · 3 · 4장과 개인정보처리방침(`/privacy`)뿐입니다. 개인정보처리방침은 4-1 의 틀을 쓰지 않고 로고 줄과 본문 카드만 두며, 로그인 · 가입 화면 아래의 링크가 새 창으로 엽니다.

| 상황 | 화면이 하는 일 |
|---|---|
| 확인 중 | 스플래시(1장)를 띄움 |
| 로그인 안 됨 (`/auth/me` 가 401) | `/login` 으로 |
| 토큰 만료 (401 · `AUTHENTICATION_FAILED`) | `/auth/refresh` 로 한 번 갱신하고 같은 요청을 다시 보냄 · **갱신이 실패했을 때만** 로그아웃 처리 |
| 갱신은 됐는데 같은 요청이 또 401 | 로그아웃하지 않고 그 화면에 오류만 보임 — 게이트웨이가 찾지 못한 서비스도 같은 401 로 돌아오기 때문입니다 |
| 프로필 없음 (`/users/me` 가 404) | 0.7초 간격으로 7번(약 5초) 다시 부름 → 그래도 없으면 자동 로그아웃 → `/login` 에 「이 계정의 정보를 찾지 못했습니다」 안내. user v0.2.2 부터 프로필 행이 없으면 서버가 그 자리에서 만들어 주므로(자가 복구), 이 404 는 **탈퇴 표시가 있는 계정**이거나 그 복구가 실패했을 때입니다 |
| 로그아웃 · 탈퇴 | `POST /auth/logout`(서버가 만료 쿠키를 내려 줌) → 세션 열쇠를 전부 지움 → `/login` |

로그아웃은 `useSignOut` 하나로 모여 있습니다. 계정 메뉴 · 자동 로그아웃 · 탈퇴가 모두 이것을 부릅니다.

### 4-3. 판정 기준 · 지역 · 날씨 띠

**판정 기준** (`BasisProvider`) — 「대표 반려동물」 · 「한 마리 골라서」 · 「모두 함께」 셋 가운데 하나입니다. 처음엔 대표이고, 고른 것은 탭을 닫기 전까지 기억합니다(세션 저장소 `pawtrail.basis`).
판정을 부르는 화면은 전부 이 기준의 반려동물 id 를 보냅니다. 반려동물이 없으면 판정 대신 「반려동물을 등록하면 동반 가능 여부를 함께 보여 드립니다」가 뜹니다.

**지역** (`RegionProvider`) — 처음엔 `.env.local` 의 기본 지역(서울 마포구)이고, 메인 · 검색의 지역 고르기로 바꾸면 기억합니다(세션 저장소 `pawtrail.region`). 검색과 날씨가 같은 지역을 씁니다.

**날씨 띠** — 메인 · 검색 · 장소 상세 · 일정 · 최근 본 장소에서 머리띠 바로 아래에 뜹니다(마이페이지 · 알림 · 관리자에는 없음).
고른 지역의 날씨를 묻고, 오늘 남은 시간에 비 · 눈 예보가 있으면 붉은 띠(닫으면 그날은 다시 안 뜸), 없으면 기온 · 하늘 · 강수확률 · 예보 기준 시각을 차분한 띠로 보여 줍니다.

| 날씨 응답 | 띠 |
|---|---|
| 비 · 눈 예보 있음 | 「마포구 오늘 오후 3시부터 비 예보 — 실내 동반 가능한 곳 미리 확인하세요!」 |
| 그 밖 | 「마포구 지금 23°C · 맑음 · 강수확률 10% · 오후 2시 기준」 |
| `stale: true` (새 발표를 못 받아 직전 발표를 줌) | 끝에 「갱신이 조금 늦어지고 있어요」 |
| 503 (예보가 아예 없음) | 띠를 숨김 |

### 4-4. 화면 폭과 배율

뿌리 글자 크기를 창 폭에 맞춰 바꾸고, 크기는 거의 전부 `rem` 으로 잡습니다(`styles/index.css`).

```css
html { font-size: clamp(14.2222px, calc(100vw / 90), 16px); min-width: 1280px; }
.shell { width: 90rem; max-width: 100%; margin-inline: auto; }
```

| 창 폭 | 1rem | 본문 폭 | 좌우 여백 |
|---|---|---|---|
| 1280 | 14.2px | 1280 | 0 |
| 1440 | 16px | 1440 | 0 |
| 1920 | 16px | 1440 | 240씩 |
| 2560 | 16px | 1440 | 560씩 |

머리띠는 화면 끝까지 늘고, 본문은 `.shell` 기둥 안에 섭니다. 크기는 창 폭 1440 에서 1rem = 16px 가 되도록 잡았으므로, 새 크기를 정할 때는 1440 화면에서 보일 픽셀 값을 16으로 나눈 값을 `rem` 으로 씁니다.

## 5. 서버 상태 규칙

### 5-1. 기본값

`app/queryClient.ts` 에 모여 있습니다.

| 항목 | 값 | 까닭 |
|---|---|---|
| 신선한 동안 (`staleTime`) | 30초 | 화면을 옮겨 다닐 때마다 같은 값을 다시 부르지 않게 |
| 창으로 돌아왔을 때 다시 부르기 | 안 함 | 시연 중 탭을 오갈 때 목록이 흔들리지 않게 |
| 조회 다시 시도 | 5xx · 연결 실패만 한 번 | 4xx 는 다시 불러도 같으므로 |
| 쓰기 다시 시도 | 안 함 | 같은 제보 · 일정이 두 번 들어가지 않게 |

### 5-2. 열쇠

자주 쓰는 열쇠는 `api/keys.ts` 에 있고, 한 화면만 쓰는 열쇠는 그 화면 파일에 있습니다.

| 열쇠 | 무엇 | 따로 정한 것 |
|---|---|---|
| `['session', 'authMe']` | 로그인한 계정 (`/auth/me`) | 5분 동안 신선 · 다시 시도 안 함 |
| `['session', 'profile']` | 프로필 (`/users/me`) | 404 면 0.7초 간격 7번 다시 ([4-2](#4-2-로그인-확인)) |
| `['session', 'pets']` | 반려동물 목록 | 곧바로 낡음 — 사진 서명 주소가 시간이 지나면 만료되어서 |
| `['favorites']` · `['recentPlaces', 크기]` · `['trending', 시도, 반려동물 id, 크기]` · `['weather', 지역]` | 즐겨찾기 · 최근 본 장소 · 인기 급상승 · 날씨 | — |
| `['search', 조건, 정렬, 판정, 쪽]` · `['searchAll', 조건, 판정]` · `['searchSummary', 조건]` | 검색 한 쪽 · 거리순용 전체 · 판정별 건수 | [8장](#8-위치-정보-원칙) |
| `['placeReviews', 장소, 정렬, 사진만]` · `['myReviews', 정렬, 쪽]` · `['reviewTags']` | 장소 후기 · 내 후기 · 고를 수 있는 태그 | 후기를 쓰거나 지우면 앞 둘과 프로필을 다시 받음 |

`session` 으로 시작하는 열쇠는 로그인 · 로그아웃 때 한꺼번에 지웁니다. 다른 계정의 값이 남아 보이지 않게 하려는 것입니다.

### 5-3. 바꾼 뒤 다시 받기

| 이렇게 바꾸면 | 다시 받는 열쇠 |
|---|---|
| 즐겨찾기 넣기 · 빼기 | 즐겨찾기 · 프로필(마이페이지 숫자) |
| 일정의 [다녀왔어요] | 일정 · 프로필 |
| 알림 읽음 · 모두 읽음 | 알림 목록 · 안 읽은 수 |
| 반려동물 등록 · 수정 · 삭제 · 대표 지정 | 반려동물 목록 · 프로필 |
| 관리자 처리 (제보 · 수정 대기 · 정정 · 재발행) | 그 화면의 목록과 건수 |

### 5-4. 오류

서버는 성공이든 실패든 `{ code, message, data, traceId }` 봉투로 답합니다. `api/client.ts` 가 성공이면 `data` 만 돌려주고, 실패면 `ApiError`(상태 · `code` · `data` · `traceId`)를 던집니다.

- **분기는 상태 번호가 아니라 `code` 로 합니다.** 같은 409 라도 `INGEST_ALREADY_RUNNING` 과 `ITINERARY_DUPLICATE` 는 화면에서 하는 말이 다릅니다.
- **서버 문구를 화면에 그대로 띄우지 않습니다.** `commonMessage` 가 연결 실패 · 권한 없음 · 그 밖을 공통 문구로 바꾸고, 화면이 아는 `code` 만 따로 안내합니다.
- 입력 검증 실패(400 · `VALIDATION_FAILED`)는 `data` 에 `[{ field, message }]` 가 오므로 해당 입력칸 아래에 붙입니다.

## 6. 개발 서버 프록시

### 6-1. 한 갈래

`vite.config.ts` 에 있습니다. `npm run dev` 와 `npm run preview` 가 같은 설정을 씁니다.

| 화면이 부르는 주소 | 넘기는 곳 | 비고 |
|---|---|---|
| `/api/**` | 게이트웨이 (`VITE_API_PROXY_TARGET` · 기본 `localhost:8080`) | 주소를 그대로 넘김 |

한때 관리자 수집 요청만 ingest 로 따로 넘기는 갈래가 있었습니다. 게이트웨이에 관리자 입구가 열리면서 지웠습니다.

### 6-2. 왜 프록시를 두나

브라우저는 화면을 내준 주소와 다른 주소로 요청하면 CORS 규칙을 적용하고, 로그인 쿠키를 싣는 데도 제약을 둡니다.
개발 서버가 `/api` 를 대신 넘겨 주면 브라우저 눈에는 화면과 API 가 같은 주소(`localhost:5173`)라 둘 다 문제가 되지 않습니다.
그래서 게이트웨이에는 개발용 CORS 설정이 없습니다.

### 6-3. 운영 화면 수집 버튼

21장 「공사 데이터 최신 수집」은 누르면 ingest 가 한국관광공사 OpenAPI 를 그 자리에서 호출해 바뀐 원문을 가져오고, 실행 기록 표에 부른 기능(`petTourSyncList2` · `detailPetTour2` 등)과 건수를 남깁니다.
게이트웨이의 관리자 입구(`ADMIN` 만)를 거치므로 개발과 배포가 같은 경로를 씁니다.

| 요청 | 모양 |
|---|---|
| 실행 `POST /api/v1/admin/ingest/runs` | 본문 `{ "source": "PET_TOUR", "runType": "INCREMENTAL" }` (고캠핑은 `GOCAMPING` · `FULL`) → 202 `{ runId }` |
| 실행이 막히는 경우 | 이미 돌고 있으면 409 `INGEST_ALREADY_RUNNING` · 같은 소스를 10분 안에 다시 부르면 429 `INGEST_COOLDOWN` · 화면이 보내지 않는 조합은 400 `INGEST_RUN_NOT_ALLOWED` |
| 기록 `GET /api/v1/admin/ingest/runs?size=10` | `{ runs: [{ id, source, runType, status, startedAt, finishedAt, fetchedCount, changedCount, progress, errorMessage }] }` |

실행 기록의 상태는 「도는 중 · 끝남 · 실패 · 한도 도달 · 중단됨」입니다. **중단됨**은 받아 오다 멈춘 것으로, 다음 실행이 그 자리를 이어받으므로 실패와 다릅니다.

매일 04:00 에도 같은 증분 수집이 예약으로 돕니다. 서버 쪽 스위치가 기본 꺼짐이라 **배포 서버에서 `INGEST_SCHEDULE_ENABLED=true` 로 켜야** 화면의 안내가 사실이 됩니다([6-4](#6-4-배포할-때)).

### 6-4. 배포할 때

- `npm run build` 가 만든 `dist/` 는 정적 파일입니다. 같은 주소에서 `/api/**` 를 게이트웨이로 넘겨 줄 앞단(nginx 등)이 필요합니다 — 화면은 API 를 늘 같은 주소의 `/api` 로 부르기 때문입니다.
- 장소 상세처럼 화면 안의 경로에서 새로 고침해도 앞단이 `index.html` 을 내주게 해야 합니다. 경로는 파일이 아니라 화면 안에서 나뉘기 때문입니다.
- ingest 의 예약 수집 스위치(`INGEST_SCHEDULE_ENABLED`)를 배포 서버에서 켭니다. 운영 화면이 「매일 04:00 에도 저절로 돕니다」라고 안내하기 때문입니다.
- 개인정보처리방침(`/privacy`)은 로그인 없이 열려야 합니다. 구글 로그인 앱을 게시할 때 이 주소를 구글 콘솔의 브랜딩에 등록합니다.
- `VITE_` 값은 **빌드할 때 파일에 박힙니다.** 카카오 키를 바꾸면 다시 빌드해야 합니다. 비밀값은 `VITE_` 로 두지 않습니다(누구나 화면 파일에서 읽을 수 있음).

## 7. 브라우저 저장소에 두는 것

서버에 둘 곳이 아직 없거나, 이 브라우저에서만 기억하면 되는 값은 브라우저에 둡니다.
**다른 브라우저 · 다른 사람과 나눠 쓰지 않습니다.** 지우려면 개발자 도구(F12) → Application → Local Storage 또는 Session Storage 에서 열쇠를 지웁니다.

### 7-1. 오래 남는 것 (Local Storage)

| 열쇠 | 무엇 | 왜 여기에 |
|---|---|---|
| `pawtrail.sampleNotification.readAt.v1` | 예시 알림을 읽은 시각 | [10장](#10-시연용-예시-자료) |
| `pawtrail.sampleAdmin.v1` | 관리자 예시 자료를 처리한 결과 | [10장](#10-시연용-예시-자료) |
| `pawtrail.admin.reindexAt` | 21장 검색 색인 재구축을 이 브라우저에서 마지막으로 누른 시각 | 마지막 실행 시각을 주는 API 가 없어서 |

옛 버전이 쓰던 열쇠 둘(`pawtrail.reviews.v1` · `pawtrail.localPhotos.v1`)은 이제 쓰지 않습니다. 후기는 review 서버에, 사진은 S3 에 둡니다. 배포 주소(`paw-trail.click`)는 브라우저 저장소가 처음부터 따로라 이 열쇠가 없고, 로컬 개발 브라우저에 남아 있으면 개발자 도구에서 지우면 됩니다.

### 7-2. 탭을 닫으면 사라지는 것 (Session Storage)

`lib/storage.ts` 의 목록에 있는 열쇠만 쓸 수 있고, 로그아웃할 때 한꺼번에 지웁니다.

| 열쇠 | 무엇 |
|---|---|
| `pawtrail.basis` | 판정 기준 (대표 · 한 마리 · 모두 함께) |
| `pawtrail.region` | 고른 지역 |
| `pawtrail.weather.dismissed` | 비 예보 띠를 닫은 날 |
| `pawtrail.search.cardCoords` | 검색 카드에 좌표가 실려 오는지 ([8장](#8-위치-정보-원칙)) |

## 8. 위치 정보 원칙

**내 위치는 우리 서버로 보내지 않습니다.** 공모전 안내가 「개인위치정보를 사업자의 서버로 보내면 저장 여부와 관계없이 위치기반서비스사업자 신고 대상」이라고 밝히고 있어서,
위치가 필요한 계산은 전부 브라우저 안에서 합니다.

| 위치를 쓰는 곳 | 어떻게 |
|---|---|
| 검색 결과 · 인기 급상승 카드의 거리 | 카드에 실린 장소 좌표와 내 위치로 브라우저가 계산(하버사인) |
| 검색의 거리순 | 아래 8-1 |
| 일정 지도의 「출발: 내 위치」 점 | 화면 지도에만 그림 |
| [안내 시작하기] 의 「내 위치 → 첫 장소」 | 사용자가 그 구간을 누를 때 카카오맵 길찾기 주소에 담아 카카오로 넘김 |
| 날씨 | 위치가 아니라 고른 지역으로 물음 |

### 8-1. 거리순

서버가 정렬해 주면 편하지만, 그러려면 내 좌표를 보내야 합니다. 그래서 순서를 브라우저가 정합니다.

```
거리순을 누름 → 같은 조건의 결과를 100개씩 끝까지 받음 (첫 쪽으로 쪽 수를 알고 나머지는 한꺼번에)
             → 장소마다 내 위치와의 거리 계산 → 가까운 순으로 정렬 → 화면에서 20개씩 쪽 나눔
```

| 조건 | 거리순 |
|---|---|
| 위치 권한을 거부함 | 꺼짐 — 「위치 권한을 허용하면 거리순으로 볼 수 있습니다」 |
| 시도 전체를 고름 | 꺼짐 — 「시군구를 고르면 거리순으로 볼 수 있어요」 (결과가 많아 끝까지 받기 무거움) |
| 검색 카드에 좌표가 없음 | 꺼짐 — 「지금은 거리순을 쓸 수 없어요」 (search v0.2.0 부터는 좌표가 실려 와 이 경우가 없습니다) |
| 결과가 1,000곳을 넘음 | 평점순으로 보여 주고 「종류나 판정을 골라 좁히면 거리순으로 볼 수 있어요」 |

검색 카드의 장소 좌표(`lat` · `lon`)는 search v0.2.0 부터 실려 옵니다. 화면은 그 좌표가 있는지 보고 거리순을 켜므로, 좌표가 빠진 응답에서도 목록은 그대로 나옵니다.
판정별 건수는 서버가 세어 준 값을 그대로 씁니다.

## 9. 출처 표기

공공데이터를 보여 줄 때는 출처를 함께 적습니다. 한국관광공사 자료는 공모전 규정의 형식을 따릅니다.

| 규정 | 이 화면에서 |
|---|---|
| 출처는 「출처: ⓒ한국관광공사」 형태로 적음 | 근거 줄 · 장소 소개 · 사진에 「출처: ⓒ한국관광공사」 · 「사진 출처: ⓒ한국관광공사」 |
| API 서비스 이름(TourAPI)만 따로 적지 않음 | 쓰지 않음 |
| 서비스 이름 · 로고에 공사 명칭 · 로고 이미지를 쓰지 않음 | 쓰지 않음 — 공사 이름은 출처 표기에만 나옴 |

출처 이름은 `lib/labels.ts` 의 `SOURCE_LABEL` 한곳에서 정하고, 서버가 준 이름을 그대로 쓰지 않습니다.

| 소스 | 기관 (`SOURCE_LABEL`) | 자료 (`SOURCE_DATASET`) |
|---|---|---|
| `PET_TOUR` | ⓒ한국관광공사 | 반려동물 동반여행 API |
| `GOCAMPING` | ⓒ한국관광공사 | 고캠핑 API |
| `CULTURE_CSV` | 한국문화정보원 | 반려동물 동반 가능 문화시설 CSV |
| `MOIS_VET` | 행정안전부 | 지방행정인허가 동물병원 CSV |
| `MANUAL` · `OWNER` | 관리자 확인 · 업장 확인 | 관리자가 고친 값 · 업장이 확인해 준 값 |

근거를 펼치면 「기관 · 자료 · 「항목 이름」 · 추출 방식 — "원문"」이 보입니다. 항목 이름은 API 원본 칸 이름(`acmpyPsblCpam` 등)을 `ORIGIN_FIELD_LABEL` 로 한국어(「동반 가능 반려동물」)로 바꿔 보여 줍니다.

## 13. 용어

| 말 | 뜻 |
|---|---|
| 판정 | 이 반려동물이 이 장소에 들어갈 수 있는지 — 가능 · 조건부 가능 · 불가 · 확인 필요 |

| 판정 기준 | 판정을 누구 기준으로 볼지 고른 반려동물 — 대표 · 한 마리 · 모두 함께 |
| 대표 반려동물 | 계정마다 하나 정해 둔 반려동물 — 판정 기준의 처음 값 |
| 근거 · 근거 원문 | 판정 이유 한 줄마다 붙은 출처 문장 · 그 문장이 들어 있는 소스별 원문 전체 |
| 출처마다 다르게 적힌 조건 | 같은 장소의 같은 조건을 소스끼리 다르게 적은 것 — 숨기지 않고 나란히 보여 줌 |
| 소스 | 데이터를 가져온 곳 — 한국관광공사 두 API · 한국문화정보원 CSV · 행정안전부 CSV |
| 증분 수집 | 바뀐 것만 다시 받는 수집 — 목록을 받아 바뀐 장소만 상세를 부름 |
| 서명 주소 | 잠깐 동안만 쓸 수 있는 S3 주소 — 사진 올리기 · 보기에 씀 |
| 봉투 | 서버 응답을 감싼 `{ code, message, data, traceId }` 모양 |
| 열쇠 · 무효화 | 서버 값을 캐시에 모아 둘 때 붙이는 이름 · 그 값을 낡은 것으로 표시해 다시 받게 하는 것 |
| 스플래시 | 로그인을 확인하는 동안 잠깐 뜨는 첫 화면 (1장) |
| 기둥 (`.shell`) | 본문을 최대 1440px 폭으로 가운데 세우는 공통 클래스 |
| 예시 자료 | 서버 자료가 없을 때만 끼우는 「테스트」 표시가 붙은 자료 ([10장](#10-시연용-예시-자료)) |
